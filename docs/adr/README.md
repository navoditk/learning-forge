# Architecture Decision Records

Architecture Decision Records (ADRs) document consequential choices that affect
the product boundary, system structure, privacy posture, or ability to reverse
course.

## Format

Each ADR should include:

- status (`Proposed`, `Accepted`, `Superseded`, or `Rejected`);
- date and decision owner;
- context and problem statement;
- decision and explicit non-decisions;
- alternatives considered;
- consequences and reversal signals;
- links to affected requirements, issues, or verification evidence.

ADRs do not replace human approval. A decision involving child safety, privacy,
legal obligations, content rights, spending, or release authority must name the
responsible reviewer and remain `Proposed` until that approval is recorded.
